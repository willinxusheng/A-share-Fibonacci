# 情绪透明化研判（R87 · 借鉴缠论 sentiment/ 模块）

> 结论先行：**本仓（A股斐波那契波浪看板）当前没有任何情绪数据源，因此不落地任何"伪造"的情绪数字。**
> 本文给出可落地的代理源方案与接入纪律，待拍板后实施。这是与缠论项目对齐的"透明化研判"缺口补齐，
> 而非把情绪塞进概率引擎。

## 一、缠论怎么做（参照实现）

缠论 `sentiment/` 模块的做法值得借鉴，且纪律严明：

- **数据**：提交原始 `涨跌家数` txt（`sh_long.txt` / `sh50.txt` / `sz_long.txt` / `zz1000.txt`，约 70–110KB），
  本地用 `calc_v2.py` 重算情绪指数，**不依赖第三方实时接口**（避免 CI 取数抖动）。
- **定位**：`monitor_only` —— 情绪指数**只用于研判提示与面板展示**，绝不并入概率/方向预测主模型。
- **健壮性**：`continue-on-error` 取数失败用兜底 `sentiment_v2.json`，不阻断每日部署。
- **透明**：在 `quality_cert.json` 中标注 `"sentiment": "monitor_only"`，让人一眼看到"情绪未参与建模"。

## 二、本仓为何不能照搬

本仓的概率引擎（首达概率 + R49 三级降级 + OOS Brier 校准）以 `data.js` 为单一真值，
OOS 闸门（双守卫 + 0.2276 基线）守护的是**生产啮合式 Brier**。若把情绪作为特征并入概率：

- 会污染 OOS Brier 的"引擎改动守门员"语义（情绪噪声被误判为引擎退化）；
- 且本仓无历史情绪序列，冷启动强行融合 = 编造校准锚点（违反 R85 反假绿纪律）。

**因此情绪在本仓只能做"透明化研判"，不能做"概率特征"。**

## 四、接入纪律（落地时必守，防假绿/防污染）

1. **monitor_only**：情绪仅展示 + 研判提示，绝不并入 `build_data` 概率合成（守护 OOS Brier 真值）。
2. **本地重算**：提交原始数据文件（如 `data/sentiment/*.txt`），CI 用脚本重算，不依赖第三方实时接口。
3. **continue-on-error**：取数失败用上次兜底值或留空，不阻断每日数据推送（与缠论同款）。
4. **透明标注**：在 `quality_cert.json` 加 `"sentiment": {"mode": "monitor_only", "source": "..."}`，
   让人看到情绪未参与建模。
5. **sole-writer 兼容**：原始数据文件由 CI 每日追加（`git add data/` 一并提交），本地只读。
