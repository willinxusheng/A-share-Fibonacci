# 情绪透明化研判（R87 · 借鉴缠论 sentiment/ 模块）

> 结论先行（R87 已落地）：**本仓情绪温度采用「内部代理 + monitor_only」落地——不伪造情绪数字、不并入概率引擎。**
> 因涨跌家数/涨停跌停只有 eastmoney 中国本地源（GitHub 海外 runner 不可达，R271 根因，无 yahoo/stooq 回退），
> 改用本仓已有单一真源 data/data.js 推导代理情绪温度。这是与缠论项目对齐的"透明化研判"缺口补齐，
> 而非把情绪塞进概率引擎。

## 一、缠论怎么做（参照实现）

缠论 `sentiment/` 模块的做法值得借鉴，且纪律严明：

- **数据**：提交原始 `涨跌家数` txt（`sh_long.txt` / `sh50.txt` / `sz_long.txt` / `zz1000.txt`，约 70–110KB），
  本地用 `calc_v2.py` 重算情绪指数，**不依赖第三方实时接口**（避免 CI 取数抖动）。
- **定位**：`monitor_only` —— 情绪指数**只用于研判提示与面板展示**，绝不并入概率/方向预测主模型。
- **健壮性**：`continue-on-error` 取数失败用兜底 `sentiment_v2.json`，不阻断每日部署。
- **透明**：在 `quality_cert.json` 中标注 `"sentiment": "monitor_only"`，让人一眼看到"情绪未参与建模"。

## 二、本仓为何不能照搬

本仓的概率引擎（首达概率 + R49 三级降级 + OOS Brier 校准）以 `data.js` 为单一真值，
OOS 闸门（双守卫 + 0.2276 基线）守护的是**生产啮合式 Brier**。若把情绪作为特征并入概率：

- 会污染 OOS Brier 的"引擎改动守门员"语义（情绪噪声被误判为引擎退化）；
- 且本仓无历史情绪序列，冷启动强行融合 = 编造校准锚点（违反 R85 反假绿纪律）。

**因此情绪在本仓只能做"透明化研判"，不能做"概率特征"。**

## 三、可行的代理源（按推荐度，免费/稳定优先）

| 候选源 | 含义 | 获取通道（免费优先） | 适配度 |
|---|---|---|---|
| ① 涨跌家数（全市场 AD） | 上涨/下跌/平家数，最接近缠论做法 | 东财 push2 / 新浪财经 大盘接口（盘中+日频）；或交易所行情文件 | ★★★★★ |
| ② 涨停/跌停家数 + 连板高度 | 情绪温度最直接的"贪婪/恐慌"指标 | 东财/同花顺 涨跌停统计接口 | ★★★★☆ |
| ③ 北向资金（陆股通净买入） | 外资风向标 | 港交所/东财 日频（注：盘中实时披露已暂停，用日频） | ★★★☆☆ |

**最终选择（R87 旭总拍板）**：涨跌家数/涨停跌停在海外 CI runner 不可达，故不照搬；
改为**内部代理情绪温度**（详见第六节），由 `gen_sentiment.py` 从 data/data.js 单一真源推导，
以 `monitor_only` 接入，渲染"🌡️ 市场情绪温度"小卡（与"📊 预测质量自检证书"并列），不参与任何概率计算。

## 四、接入纪律（落地时必守，防假绿/防污染）

1. **monitor_only**：情绪仅展示 + 研判提示，绝不并入 `build_data` 概率合成（守护 OOS Brier 真值）。
2. **本地重算**：提交原始数据文件（如 `data/sentiment/*.txt`），CI 用脚本重算，不依赖第三方实时接口。
3. **continue-on-error**：取数失败用上次兜底值或留空，不阻断每日数据推送（与缠论同款）。
4. **透明标注**：在 `quality_cert.json` 加 `"sentiment": {"mode": "monitor_only", "source": "..."}`，
   让人看到情绪未参与建模。
5. **sole-writer 兼容**：原始数据文件由 CI 每日追加（`git add data/` 一并提交），本地只读。

## 五、落地结果（R87）

- **数据源拍板**：不做 ①+②（涨跌家数/涨停跌停，海外 runner 不可达）；采用**内部代理情绪温度**。
- **实现**：新增 `gen_sentiment.py`，从 `data/data.js` 单一真源推导 0~100 情绪温度 + 五档定性
  （冰点/偏冷/中性/偏热/狂热），五维合成见第六节；写 `data/sentiment.json` + `data/sentiment.js`。
- **接线**：`daily.yml` 加 gen_sentiment 步骤（continue-on-error、退出码恒 0 不阻断）；
  `gen_quality_cert.py` 加 `sentiment` 透明标注字段（mode=monitor_only）；`index.html` 渲染
  "🌡️ 市场情绪温度"小卡（与"📊 预测质量自检证书"并列）。
- **情绪从未写入任何概率数字** —— 这是对"反假绿"纪律的坚守。

## 六、代理情绪温度合成（实现细节）

五维（各映射到 [-1,+1] 子分，加权求和 → 0~100，clamp[0,100]）：

| 维度 | 权重 | 子分来源 |
|---|---|---|
| 趋势动量 | 0.30 | 上证 ret20（20 日涨跌幅），clamp(ret20/8) |
| 牛熊位置 | 0.20 | (lastClose − MA250)/MA250，clamp(dev/0.15) |
| 量能水平 | 0.20 | 上证 vol20/vol250 − 1，clamp(ratio/0.5) |
| 波动恐慌 | 0.15 | volRegime.pctile（HV20 五年分位，高波动=恐慌），1 − pctile/50 |
| 广度确认 | 0.15 | (宽基 resonance.breadth + 跨市场 crossMarket.breadth)/2 |

诚实标注：这是「量能/动量/波动/广度」合成的代理情绪温度，**非全市场涨跌家数**；
量能维度受跨源 volume 单位差异影响，仅作相对参考。全部数据来自 data.js 单一真源，
不新增第三方接口、不破坏 sole-writer、CI 每天稳定可算。
